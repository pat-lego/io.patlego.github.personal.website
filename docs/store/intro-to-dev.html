🎒 What to Bring

A laptop (Windows or Mac) with its power cable. No software installs needed ahead of time — we'll get Node, Python, and Java set up together on day one.

Why does this matter?

A program is just a list of instructions a computer follows, in order, one at a time. That's really it — every other idea in programming is a variation on that. Most "intro to coding" material jumps straight into building an app, which means you spend more time fighting an editor and installing tools than actually learning what code does. This course skips all of that: you type one line into a shell, you see exactly what happens, and you build up ideas one at a time before ever touching a real project.

Tools you'll use

Node REPL (node) Python Shell (python3) Java Shell (jshell)

That's it — each of these opens a prompt in your terminal where you can type a line of code and immediately see what happens. No files, no compiling, no real projects yet.

Curriculum

Module 1

What is a variable?

Using the Node, Python, and Java shells side by side to store a value in a name, print it back out, and change it. You'll see the exact same idea expressed three different ways.

Node 
let age = 16;
console.log(age);
Python 
age = 16
print(age)
Java (jshell) 
int age = 16;
System.out.println(age);

⚠️ Common mistake: forgetting that age and Age are two different variables (all three languages care about case), and that Java makes you state the type (int, String) up front while Node and Python don't.

Module 2

Objects vs. Primitives

Poking at numbers, strings, and booleans versus objects directly in the shell to build an intuition for what's a "plain value" and what's a container with its own properties.

Node 
typeof 16
// "number"
typeof { age: 16 }
// "object"
Python 
type(16)
# <class 'int'>
type({"age": 16})
# <class 'dict'>
Java (jshell) 
int x = 16;
// primitive
var obj = Map.of("age", 16);
// object

⚠️ Common mistake: assuming copying a variable that holds an object copies its contents too. In all three languages it actually copies a reference — change the object through one name and the other name sees the change as well.

Module 3

Functions

Writing tiny one-line functions right in the shell, calling them, and seeing what they return — the smallest possible building block for reusable code.

Node 
function greet(name) {
  return "Hi " + name;
}
greet("Sam");
Python 
def greet(name):
    return "Hi " + name

greet("Sam")
Java (jshell) 
String greet(String name) {
  return "Hi " + name;
}
greet("Sam")

⚠️ Common mistake: forgetting the return keyword and expecting a value to just "come out" of the function on its own. Without it, your function runs but hands back nothing useful.

Module 4

Control Flow: if/else and Loops

Making decisions and repeating steps — the moment code stops just running top to bottom and starts actually "thinking" based on a value.

Node 
if (age >= 16) {
  console.log("go for it");
} else {
  console.log("not yet");
}
for (let i = 0; i < 3; i++) {
  console.log(i);
}
Python 
if age >= 16:
    print("go for it")
else:
    print("not yet")

for i in range(3):
    print(i)
Java (jshell) 
if (age >= 16) {
  System.out.println("go for it");
} else {
  System.out.println("not yet");
}
for (int i = 0; i < 3; i++) {
  System.out.println(i);
}

⚠️ Common mistake: mixing up = (assigns a value) with ==/=== (compares two values) inside an if condition — one of the most common bugs in every language on this list.

Module 5

Interpreted vs. Compiled Languages

Why Node and Python let you run code line-by-line while Java normally needs to be compiled first — and why jshell gives Java that same instant, REPL-style feedback for this course.

Node 
node app.js
// runs immediately
Python 
python3 app.py
# runs immediately
Java (jshell) 
javac App.java
java App
// compile, then run
// (jshell skips this for now)

⚠️ Common mistake: expecting jshell to behave exactly like a real Java project. It's a REPL, not a compiler — once you write actual .java files, you'll need to run javac before java, and it will catch mistakes jshell doesn't.

Once you're comfortable typing code directly into these shells, the next course picks up right where this one leaves off: writing your first real .js, .py, and .java files, saving them, and running them for real.
